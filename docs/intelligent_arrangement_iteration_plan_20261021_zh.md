# 智能编曲本轮迭代更新计划

日期：2026-10-21。状态：实施前计划，本文新增能力均未因写入计划而视为已实现。

建议发行目标：下一定制预览版，暂称 `0.3.1-preview.5`；实际版本在封版时确定。基于当前 Preview.4 工程迭代，官方基座升级单独审查兼容性。

## 1. 输入、范围与判断依据

本计划综合以下报告及用户对真实采样、AI 素材、VST、自然演奏、Ocho、音乐理解和专业评价的要求：

- [深度分析及问题报告](./intelligent_arrangement_deep_audit_20261020_zh.md)。
- [未来迭代规划报告](./intelligent_arrangement_next_plan_20261020_zh.md)。
- [本地模型、音乐理解与云端接入分析](./local_models_and_music_understanding_20261020_zh.md)。用户两次引用的模型报告是同一文件。
- 当前分支 `intelligent-arrangement-v031`，应用代码提交 `fc7c617`，已发行 Preview.4 的源码快照 `10b0f217`。
- 本轮只读核查当前源码、模型规范、工程记录及官方技术资料；未重新生成音频、试听判定音色、执行付费云端分析或修改用户作品。

2026-10-20 报告是历史快照，不能将其中“待新增”全部当作当前缺失。Preview.4 已有历史快捷切换、问答卡、库存搜索、下载确认/进度、素材复用、时长与参考音频入口；本轮应复用并加强这些能力。

### 1.1 本轮产品目标

让智能编曲能基于可用资源交付符合要求的素材、自然拼合的音乐和可编辑工程，并能准确解释失败原因。重点是三条链：

1. **规划与实际来源一致**：用户限定真实、AI 或混合后，每个声部实际采用的音源符合限制。
2. **生成与音乐要求一致**：目标乐器、声音类别、谱条件、时长与实际结果分别检查；不再以“生成了文件”代表备料合格。
3. **助手与页面一致**：Ocho 使用同一库存、修订、任务、验收和拼合服务；读取实际音频的分析工具为其提供证据。

### 1.2 本轮完成定义

- 当前箫声部和旧合唱异常有可追溯诊断、可撤销修复与真实模型对照结果。
- 真实、AI、混合三种模式均完成规划、审核、写谱、备料、验收、试听、拼合、导出和重开。
- 仅真实模式不得混入 AI 或未声明的合成模拟；AI 模式不得把真实录音标成 AI 生成。
- 普通语音、故事、音乐生成、SF2 编曲、声音库、既有设置和 Preview.4 交互完整回归。
- Windows 安装包、单安装覆盖升级、备份与发布附件核验全部完成后，才能声明本轮交付完成。

## 3. 保持的产品结构与界面约定

按用户明确要求保持一级入口次序：**音乐生成 → 智能编曲 → 编曲**；**声音库后为音源库与乐器**。旧报告中与该次序不一致的描述，以这里为准。

- 插件安装、扫描、原生编辑器与宿主维护继续归设置管理。
- 原设置中的“编曲音色库”保持原用途；音源库只增加对应能力入口，不把模型下载迁出设置。
- AI 生成素材、AI 生成模型、音乐分析模型、SF2 预览音色分清用途；延续现有二级分类，避免扩大一级导航。
- 复用官方声音库列表、搜索、详情与 Astryx 组件。列表只放关键字段，模型参数、许可、检测依据和历史放二级详情。
- Preview.4 的历史切换、行高、问答卡、试听进度、面板调高/收起、横向平移等作为受保护回归项。

智能编曲主界面以阶段和下一步组织：

```text
需求与参考 → 规划与选源 → 曲谱 → 素材准备与验收 → 时间线与成品
```

每个声部行显示：乐器、来源类型、实际音源、执行方式、状态、下一步操作。详情提供“替换来源、生成设置、原始/适配试听、问题、历史”。“已下载”和“本句可演奏”分别显示。

## 4. 工作包 A：来源与任务合同（P0）

### 4.1 分开记录四个维度

| 维度 | 内容 |
| --- | --- |
| 声音出处 | 真实录音、AI 生成、合成模拟、混合、未知 |
| 实现后端 | 采样演奏、VST3、AI 音频生成、用户导入演奏 |
| 素材形态 | 单音、多采样乐器、持续音、独立乐句、循环、效果、整曲 |
| 验收状态 | 文件健康、内容检查、对齐状态、人工试听结论 |

VST 只是后端，不自动代表真实；AI 乐句只是片段，不自动具有多音高、多力度的可演奏映射。

### 4.2 来源选择

1. 用户显式绑定且锁定的来源优先校验；失效时报告，不偷偷换源。
2. 查询适用且健康的本地来源，包括真实采样、已生成 AI 素材、已验证插件预设与乐队组合。
3. 按来源政策、用途、音域、奏法、质量、生成成本和下载成本选择下一步：复用、生成、提出下载或要求手动导入。
4. 本地候选不适用应说明是奏法、音域、形态、文件或身份问题；不能仅因有同名文件就使用，也不能一律重新联网。
5. 仅真实模式没有合格来源时等待替换或补料；切换为 AI 必须由用户明确决定。混合模式由计划解释各句选择的实际依据。

保留默认最大移调 7 个半音。琵琶轮指、挑弹必须有对应映射或明示的模拟方式。真实轮指、插件轮指、重复挑弹模拟不能共用同一验收标签。

### 4.3 新增合同

沿用现有 PartID、修订指纹和持久任务，追加最小必要字段：

- `SourceCapability`：来源、后端、形态、音域、力度、奏法、连续性能力及证据。
- `MaterialContract`：当前声部/演奏实例、输入修订、任务类型、音符条件、起止音乐时间、目标核心长度、尾音策略与来源限制。
- `MaterialRealization`：原始文件哈希、真实请求摘要、原始长度、有效区段、音频检查、适配操作、试听状态与适配器版本。
- `InstrumentInstance`：跨句共享的演奏者/音源/预设身份。
- `RenderManifest`：实际素材与区段、时间基准、增益/接缝策略、导出配置和依赖。

稳定 ID 由后端管理；模型不生成路径、不替代文件健康检查、不自行确认验收。

**验收门槛：** 已下载健康音源不联网；错误绑定可局部替换且撤销；仅真实模式不会因缺料自动变 AI；当前“AI 来源/真实理由”矛盾能在审核前准确显示。

## 5. 工作包 B：AI 乐句生成与内容验收（P0）

### 5.1 按任务生成提示和参数

- 器乐：仅当前乐器、演奏技法、节奏/调性、当前音乐角色、当前乐句与有限上下文；避免原样塞入整首其他配器或剧情。
- 无词人声：明确元音、声部织体与人数感，不传器乐禁人声参数；不等同于带歌词歌曲。
- 打击/环境：允许非音高任务，避免强迫转成旋律 ABC。
- 跟谱乐句与自由音频分别显示；模型接收了谱条件，只能标为“谱条件生成”，不能标成“已验证逐音符跟谱”。
- 已有短句不自动转成通用单音乐器。可演奏 AI 音色导入必须另外验证根音、力度、奏法、持续/释放和可移调范围。

### 5.2 模型能力注册

每个能力对应“模型版本 + 引擎版本 + 适配器版本 + 实测任务”。返回支持、不支持、实验性和未验证，界面据此展示。

| 路径 | 本轮定位 | 验收重点 |
| --- | --- | --- |
| YuE2 | 谱条件音乐/乐句候选 | 乐句时值、调性、模式、长度预算、人声泄漏、独立声部表现 |
| ACE-Step 当前 Turbo 路线 | 可控长度的自由音乐候选 | 仅传当前引擎支持的参数；不宣称严格跟谱或已有 Extract |
| ACE-Step Base/SFT 分轨能力 | 专项调研与接入验证 | 上游有能力不等于当前引擎已接通；成功前不启用正式选项 |
| 已登记真实采样或 VST 预设 | 准确乐器演奏的重要路径 | 音域/奏法与整轨实机渲染，不以模型名称替代验证 |

本轮必须有一条真正通过验收的 AI 乐句路径。若某模型在当前硬件上不能稳定完成独立民乐声部，应明确降为候选/实验性；不能以“已禁用所有 AI 生成”作为本轮目标完成。

### 5.3 指定长度

默认跟随曲谱本句；高级设置允许小节或秒数，展示：目标音乐长度、模型请求预算、原始返回长度、有效成品长度、尾音。

- YuE2：核对安装内核的实际选项，接入编曲专用 `semantic_min_tokens` / `semantic_max_tokens`，校验范围和前缀，记录是否达到预算而截断。v0.9.1 文档声明语义帧为 25 帧/秒；9 秒约 225 帧仅是预算换算，最终以解码帧数与音乐事件验收为准。
- ACE-Step：使用实际支持的长度参数和最短请求规则，短于模型下限时明示原片与所需区段的区别。
- 所有模型：拒绝将极端超长结果默认取开头并认定适配完成；不能通过极端加速、静音补齐或硬裁乐句冒充指定长度成功。
- 未知调性不得静默写为 `K:C`。`D minor` 等等价名称归一；中国调式保存原义与已确认音阶，不擅自等同西方大小调。

### 5.4 状态和入库

```text
待准备 → 生成中 → 原始文件已保存 → 技术检查
                                      ↓
                              内容/对齐检查
                                      ↓
                           待适配 / 待试听 / 不合格
                                      ↓
                              当前合同验收通过
                                      ↓
                                   可拼合
```

“已入库”允许保存不合格原片便于试听和排错，但默认自动检索不能把它作为合格乐句使用。已有素材人工确认仍保留；旧确认不自动获得新合同的技术合格状态，显式选择旧素材可用于历史工程。

内容检查结合本地测量、音频理解/专用检测、用户试听：没有检测能力时显示未知；模型判断与用户标注冲突时保留双方依据，不伪造确定结论。确认卡不能绕过缺文件、非法范围、来源冲突等硬错误。

自动重试初始上限为每目标额外 2 次，属于产品预算初值，实施时可调整；超过后展示结果和卡点，不无限烧算力或付费调用。重试失败保留已完成素材。

**验收门槛：** 3/9/30 秒目标、当前 9.23 秒箫和旧 9 秒合唱均有真实请求与原片记录；明显不符的结果被拦截。任何适配区段都应覆盖所需音乐事件，不仅仅 WAV 帧数相等。

## 6. 工作包 C：连续演奏、接缝与导出保真（P0）

### 6.1 时间与演奏

- 曲谱音乐时间经唯一 TempoMap 转为秒与采样帧；固定速度和变速分别回归。替换过程保留当前不支持变速时的拒绝保护。
- 同一乐器实例相邻句优先整轨采样/VST 演奏。保留已有按来源和轨道分组代码，不重写已经正确的合并路径。
- 连音、音符释放、短样本可持续时长作为来源能力。无循环/释放/连奏能力的短样本不能宣称可无限吹奏箫长音。
- 琵琶轮指、挑弹使用明确奏法映射；同一演奏者采用连续、可复现的时序与力度策略，保护有意呼吸和断奏。
- 箫气声、琵琶滑音、自由速度不套用单一机械对齐阈值。

### 6.2 接缝

| 情况 | 处理 |
| --- | --- |
| 同源且源偏移连续 | 连续排程或合并片段，不额外重复淡入/淡出 |
| 跨源同一声部 | 查起音/节拍/尾音，再选择重叠与曲线，检查相位与响度 |
| 有意呼吸/休止 | 保留留白，不自动填音 |
| 源文件自身音符重起音或缺尾音 | 修演奏或换素材，不能靠时间线合并掩盖 |

新增接缝策略版本，试听和导出使用同一增益定义。旧作品默认保留原行为，用户应用新策略后产生新修订。

### 6.3 导出

- 音乐导出默认提供 48 kHz 立体声 WAV，可选 44.1 kHz；位深按编码器实际支持展示并验证。
- 原版语音导出保持原设置语义。参数界面显示实际声道与采样率，不把更高采样率称为恢复原本不存在的细节。
- 当前 `OfflineAudioContext(1, ..., 24000)` 改为显式音乐导出配置；核对下混、声像、峰值、尾音及音轨效果是按轨还是按片段应用，避免接点重启动态处理器。
- 混音/分轨与可编辑工程分别导出。工程保留未拼合素材的引用与依赖；插件二进制、受限制音色不随包复制。
- 90 秒交付区分“音乐主体 90 秒 + 尾音”和“文件严格 90 秒”。严格文件长度不能靠提前切断演奏伪造音乐完成。

**验收门槛：** 左右声道独立测试通过；无意外降为单声道；固定样本证明同源接点无新增空白/包络凹陷。小提琴 18/24/42 秒和真实箫/琵琶分轨作原始/改进 A/B。音乐预览与导出效果一致，其他语音功能保持通过。

## 7. 工作包 D：音乐听辨和多维评价第一版（主线配套）

### 7.1 分工

| 角色 | 工作 |
| --- | --- |
| DeepSeek 或现有文本模型 | 需求理解、规划、读工具结果、提出修改 |
| 本地信号/音乐特征工具 | 长度、静音、削波、响度、起音、接缝、可测的音高/节拍候选 |
| 实际接收波形的音频模型 | 人声/乐器候选、织体、段落与听感解释，返回不确定性 |
| 用户 | 确认艺术方向、试听和是否采用修改 |

DeepSeek API 配置不自动具有音频理解能力。只有向音频适配器提交真实片段后，Ocho 才能说“本次分析了这段音频”。

### 7.2 接入选择

- 本轮先交付本地信号诊断；云端按 Qwen-Omni 优先验证、Gemini 对照的顺序接入实际音频输入。
- 设置中将“规划模型”和“音乐听辨服务”分开，可沿用现有凭证存储与供应商组件，但请求协议单独实现。
- 模型名称、区域、音频格式、大小/时长限制和价格以实施时官方文档及账号可用性为准，不将历史报告里的名字硬编码为永久默认。
- 上传前展示具体素材、片段范围、用途和费用限制；复用本次已授权范围，不对每个子调用重复弹窗。无凭证或仅本地模式仍可用测量、真实/VST 演奏和人工试听。
- Audio Flamingo Next 作为本地候选：以本机实际显存/内存盘点、许可和短片段性能测试决定是否公开启用，不能与 YuE2 同时强行常驻。
- SheetSage2 提供旋律/和弦候选；Basic Pitch、节拍工具和语义检索按专项基准评估，不将装上这些模型等同于已解决民乐总谱识别。

云端正式能力需至少一个供应商真实调用、格式/超时/重试/取消和费用记录通过。缺账号或专项验证时该能力仍属未验收，不计入本轮已完成清单，也不能用模拟结果补足。

### 7.3 音乐评价不是单一总分

| 维度 | 主要证据 | 第一版输出 |
| --- | --- | --- |
| 歌词与表达 | 用户提供歌词、结构、听到的实际表达 | 意象、结构、咬字适配建议；纯器乐显示不适用 |
| 旋律与和声 | 乐谱、音高/和弦候选、音频 | 动机、发展、张力、重复与和声连接 |
| 配器与层次 | 实际分轨、计划、混音 | 主次、频段/节奏遮蔽、进入退出、密度 |
| 演奏与奏法 | 独立声部音频、采样/预设映射 | 轮指/挑弹候选区间、长音、连奏、呼吸、力度 |
| 演唱表现 | 足够清晰的人声或分轨 | 音准、节奏、稳定性、气息/灵动的可听描述；不作生理诊断 |
| 混音与音质 | 波形、立体声/响度测量、听音 | 削波、空间、平衡、刺耳、接缝、失真候选 |
| 结构与审美 | 用户目标、参考曲、音频 | 克制、情绪弧线、独特性等带依据的主观建议 |

每条结论显示时间范围、证据类型、适用条件、未知项和建议操作。模型自报置信度未经校准不显示成准确率；“甜美”“高级”保留为偏好判断，不能包装成客观专业鉴定。

盲测隐藏文件名和配器标签，加入箫/竹笛、琵琶/古筝、人声/气声、弦乐与合成垫对照；首版至少 24 个明确许可的短片段，并记录误报、漏报和不确定项。阈值在基准结果后冻结，不能先写虚构的识别率。低可靠模型只能给建议，不能自动拒绝或采用素材。

## 8. 工作包 E：Ocho 的真实执行闭环（P0）

复用现有问答卡、库存搜索、下载确认和编曲工具，补齐业务缺口：

1. 增加专用智能编曲技能，保留普通 SF2 编曲技能，按真实/AI/混合/VST/库内音源意图路由。
2. 读取当前作品、修订和资源；方案差异与审核在页面或聊天卡中针对指定修订确认。
3. 计划修改、来源替换、素材检查/适配、插件预设查询、接缝诊断、导出准备使用同一 Go 业务入口。
4. 任务返回 ID 后由应用管理；Ocho 读实际子任务与检查结果，再进行下一步。对话结束不等于任务取消或完成。
5. 对超长、错乐器、人声泄漏候选，先报告、局部返工或提出替换，不修改全曲来源偏好、不覆盖锁定音源和人工编辑。
6. 网络搜索只产生候选；下载通过已有清单确认、校验、试听/能力核查再入库。登录站保持官方登录/下载后导入，除非另有可用正式集成。
7. 只能选择已登记且验证过的 VST 预设；原生编辑器交互由用户完成。不能因找到了 DLL/VST3 文件就宣称会演奏所需民乐。
8. 没有提交实际音频分析时不能宣称听过；启动任务只能报告已启动。完成消息分列已规划、已写谱、已备料、已验收、已拼合、已导出。

接口名称沿现有 RPC/MCP 风格实施，建议新增/扩展 `arrangement.status`、计划 patch/approval、material inspect/fit、seams inspect、`music.inspectAudio`、`music.analyze`、preset query 和 export plan。避免为同一业务建立前端、助手两套实现。

**验收门槛：** 使用真实 DeepSeek 配置完成一次完整对话制作和一次失败恢复；页面与工具读取一致；确认前不越过审核；晚到结果不覆盖新修订；已有任务成功部分保留。

## 9. 工作包 F：音源库、插件与操作体验（P0 必要项，扩展分级）

- 本地音源可直接替换当前声部并保留曲谱；不适用候选显示具体理由，替代音色必须明确标记。
- 列表状态包含“已下载/需修复/待确认/本句可用”，详情显示逐个采样试听、根音、力度、奏法、完整路径和来源。
- AI 详情显示原始与有效长度、当前任务类型、模型能力、检查区间与 A/B；允许单项重做、有效区段选择和撤销。
- 已生成 AI 乐句和各种本地音频可以复用，默认保留 `clip` 形态；只有经过映射验证的单音才进入可演奏乐器候选。
- 乐队组合保存来源/预设、角色和奏法能力；套用前查文件与目标曲谱适用性，不能复制上一首歌曲的音符与缓存。
- 插件继续提供安装/扫描、宿主测试、预设试听、整轨渲染三个分明入口；本轮至少使用一个实际民乐预设完成完整 MIDI、控制信息、尾音、保存重开测试。
- 外站来源保留 Pianobook、Decent Samples、LABS、DSK、Kong Audio 等已有入口与导入路径；逐个核对实际插件格式、架构、许可与登录要求，不宣称所有站点能一键自动下载。

## 11. 实施顺序与阶段出口

本轮按同一个交付目标分阶段实施；技术候选包不能提前作为“完整智能编曲可用版”。以下为工作分解，不是已执行进度或固定工期承诺。

| 阶段 | 实施内容 | 阶段结束证据 |
| --- | --- | --- |
| S0 基线 | 冻结 Preview.4、备份、实际请求审计和故障样本；新旧报告状态对齐 | 当前箫/合唱合同及原片、请求摘要、现有功能基线 |
| S1 可信备料 | A+B：来源、任务类型、长度预算、调性、素材验收/适配、局部重试 | 实际 AI 短乐句通过；超长/错内容被拦；真实模式保持 |
| S2 音乐交付 | C：时间、持续演奏、接缝、立体声导出、VST 实轨 | 分轨 A/B、预览导出比较、工程重开 |
| S3 听辨与助手 | D+E：本地测量、至少一个实际听音适配验证、专用技能与审核/任务闭环 | 音频输入证据、盲测报告、真实 DeepSeek 全流程日志 |
| S4 体验与发布 | F、跨模块回归、迁移/回滚演练、安装版实机检查、打包/上传 | 单一安装升级、原配置保留、附件与源码一致 |

听音供应商研究与测试样本准备可在 S1 开始；助手合同设计需同步于 S1，避免到 S3 再重建接口。发布前整合验收必须覆盖整条链，不能把各阶段通过率相加宣称成功。

本轮不排入训练民乐基础模型、通用 DAW 重写、任意 VST 界面全自动操作、付费/登录网站通用爬取、一键专业人声修音和自动审美总分系统。这些另列后续研究，不挤占当前生成/演奏可靠性。

## 12. 验收清单与指标

| ID | 用例 | 通过标准与证据 |
| --- | --- | --- |
| T01 | 9.23 秒箫 | 原始请求、模式、ABC、长度预算可追溯；原片/有效段 A/B；有可用独立箫候选，或模型明确不支持且提供已验证替代，不能把错素材计成功 |
| T02 | 9 秒合唱 | 不再传相互冲突的器乐禁人声参数；无词人声实际试听，长度与核心乐句覆盖检查 |
| T03 | 器乐混入人声 | 人工标注区段与检测结果对照；有问题/未知不自动采用，保留原片并只返工相关声部 |
| T04 | 来源限制 | 已下载健康来源不触发下载；真实/AI/混合、手动锁定、替代音色分别通过；无静默越权替代 |
| T05 | 调性/时间 | D minor/Dm 等价；未知中国调式不退 C；3/9/30 秒、3/4、6/8、句内休止和变速校验 |
| T06 | 自然演奏 | 琵琶挑弹/轮指、箫长音/呼吸、弦乐接音分轨；同源连续切片不重复淡化；有意留白保留 |
| T07 | 音频保真 | 48 kHz 立体声输出、左右声道独立信号、真峰值/样本峰值按实际方法标记、削波/尾音检查；旧语音导出回归 |
| T08 | 局部变更 | 一音修改只失效相关谱条件素材；第四项失败保留前三项；重启恢复；过时后台结果不覆盖手改 |
| T09 | VST | 实际预设完整 MIDI 与尾音、重开状态一致；缺依赖与插件崩溃准确报告；宿主测试音不充验收 |
| T10 | 听音 | 实际提交音频哈希/区间/供应商/模型记录；标题矛盾盲测；结果区分测量/推测/用户标注 |

| T12 | 整曲 | 90 秒琵琶+箫，明确独奏和轮指/挑弹；真实、AI、混合各一个工程均能分轨试听、导出、换目录重开 |
| T13 | 兼容 | 语音、故事、歌曲、SF2、声音库、设置及 Preview.4 全部指定交互回归 |
| T14 | 发布 | 安装与一致性数据库备份、追加迁移、同安装标识、DeepSeek 配置/模型/音源保留、源码/安装包哈希与版本一致 |

技术指标：

- 标注不符、损坏、来源冲突或未验收素材被自动当合格采用的数量为 **0**。
- 核心时长按输出采样帧检验；允许分开保留尾音。合格还需音乐事件覆盖，不能单靠定长文件。
- 合成信号连续切片与未切片基线差异设确定性阈值；真实演奏不设未经实验的统一“自然度分数”。
- 使用至少 24 个听辨样本报告逐类结果；不编造民乐准确率门槛，未经验证的模型不得承担自动硬判定。
- 最终验收报告列出真实成功数、失败数、未执行数、硬件/模型/插件版本；未执行不计通过。
